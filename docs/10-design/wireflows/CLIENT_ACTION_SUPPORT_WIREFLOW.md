# Wireflow — Client Action, Approval & Support

Status: EXPERIENCE WIREFLOW v0.1

## Goal
Client can understand project/service state and act without calling HILTECH for routine status.

---

# Client Home — My HILTECH

```text
My HILTECH

Actions for you
- Variation #4 needs approval
- Handover package ready

Projects
- Project A 72%
- Project B Delivered

Support
- 1 open ticket
```

No internal project noise.

---

# Client Approval

```text
Actions for you
 ↓
Variation #4
 ↓
Summary
Scope change
Schedule impact
Client price impact
Supporting docs
Exact version
 ↓
Approve / Reject / Comment
 ↓
Re-auth if policy
 ↓
Authoritative decision
 ↓
HILTECH project updates
```

Never expose:
- internal cost.
- margin.
- supplier comparison.
- private internal notes.

---

# Superseded Variation

If HILTECH changes variation:
old client approval request becomes superseded.

Client sees:
```text
This request was updated.
Review latest version.
```

---

# Handover

```text
Project
 ↓
Handover
 ↓
Package v2
 ↓
Drawings
Tests
Asset register
Warranties
```

# Support Ticket

```text
Support
 ↓
New Request
 ↓
Choose:
Project/Site/Asset
 ↓
Category
Description
Photo
Urgency
 ↓
Submit
 ↓
Coverage check
 ↓
Ticket created
```

Client does not need to understand internal team/module names.

---

# Ticket Detail

Shows:
- ticket code.
- status.
- next action.
- appointment.
- client-visible timeline.
- SLA where contractual.
- resolution.

Not:
- internal technician notes.
- blame/investigation.
- internal commercial discussion.

---

# Waiting on Client

```text
Ticket
WAITING ON YOU

Need:
site access approval

[Provide access info]
```

After action:
ticket resumes.

---

# Out-of-Contract

```text
Request submitted
 ↓
Coverage = out of contract
 ↓
HILTECH review
 ↓
Possible quote
 ↓
Client decides
```

Never silently bill.

---

# Maintenance

Client sees:
- next visit.
- covered assets/sites.
- completed visit report.
- findings.
- recommended action.

Finding can create:
support ticket or quote.

---

# Billing

Client finance role only:
- invoices.
- due status.
- payment references.

Technical client role may not see billing.

---

# Mobile / Desktop

Mobile:
actions/support/status.

Desktop:
documents, handover review, multi-project visibility.

Same objects.

---

# Success Criteria

Client can answer:
- What is happening?
- What needs me?
- What was delivered?
- What support do I have?
without contacting HILTECH for basic information.
