# Wireflow — Handover to Maintenance

Status: EXPERIENCE WIREFLOW v0.1

## Goal
Make handover the natural result of project truth and carry delivered infrastructure into warranty/maintenance instead of ending in a dead folder.

---

# Delivery Review

```text
Project nearing completion
 ↓
Handover Completeness
 ↓
Required artifacts
```

Example:
✓ As-built drawing
✓ Asset register
✗ OTDR Site 3
✓ Warranty
✗ Training record

---

# Missing Artifact

Click missing item:
opens source work/document requirement.

No manual handover checklist detached from project if system can derive it.

---

# Package

```text
All mandatory ready
 ↓
Generate Handover Package v1
 ↓
Internal Review
 ↓
Correction?
 ├─ yes → v2
 └─ no
 ↓
Client Review
```

---

# Client Decision

```text
Client receives exact package version
 ↓
Accept / Comment / Reject
```

If package changes:
old acceptance superseded where appropriate.

---

# Delivered

After acceptance:
- project becomes DELIVERED.
- warranty periods begin.
- billing eligibility may change.
- site/assets stay live.

---

# Warranty

```text
Delivered Asset/Site
 ↓
Warranty Coverage
 ↓
Issue arrives
 ↓
Coverage check
 ↓
Warranty Ticket
```

---

# Maintenance Conversion

```text
Delivered
 ↓
Service/Maintenance Contract
 ↓
Covered Sites/Assets
 ↓
Preventive Schedule
 ↓
Visit generated
 ↓
Technician executes
 ↓
Findings
 ↓
Follow-up / Ticket / Quote
 ↓
Next Due
```

---

# Renewal

Before contract end:
- performance.
- incidents.
- asset condition.
- open actions.
- renewal opportunity.

No silent automatic renewal.

---

# Success Criteria

A delivered project becomes a maintained digital asset history, not an archived PDF folder.
