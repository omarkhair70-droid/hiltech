# HILTECH Iconography

Status: RESEARCHING / NOT FROZEN

## Thesis
Use a strong general-purpose icon foundation for common actions, then design a small HILTECH domain-symbol layer for infrastructure concepts generic libraries do not represent well.

Do not draw every generic icon ourselves.

---

# 3. Icon Rules

- consistent optical weight.
- use established size grid.
- monochrome by default.
- status color only when icon acts as status.
- label uncommon domain icons.
- touch target larger than glyph.
- directional icons mirror in RTL only when direction semantics require it.
- object identity icon != action icon where ambiguity exists.

---

# 4. Animated Icons

Rare.

Possible:
- sync.
- scanning.
- network activity.
- loading.

Avoid animated icons throughout dense lists.

---

# 5. Reference Principles

Carbon's icon guidance reinforces:
- consistent artboard sizing.
- icon/text optical pairing.
- large enough interactive targets.
- color should communicate action importance, not decoration.
