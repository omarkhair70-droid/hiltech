# UI / UX Reference Research Plan

Status: PLANNED
Freeze gate: REQUIRED before Design System and surface freeze.

## Why this phase exists
HILTECH must not become a generic ERP UI, a copied dashboard, or a visually dead enterprise application. Interface research is a dedicated project phase, not memory-based inspiration added during implementation.

## When it happens
After:
1. Human map.
2. Company reality map.
3. Domain/object/state/event maps.
4. Core workflows.
5. Permission model.
6. Information architecture.

Before:
- Final screen architecture.
- Design system freeze.
- Motion system freeze.
- Production UI implementation.

## Research tracks
### Enterprise operating systems
Study how modern systems manage:
- dense information,
- approvals,
- command centers,
- activity,
- search,
- permissions,
- cross-device continuity.

### Construction / field operations
Study:
- project -> site -> work navigation,
- field evidence,
- offline flows,
- drawings,
- handover,
- issue management.

### Asset / warehouse / fleet
Study:
- custody,
- scanning,
- physical/digital identity,
- movements,
- maps/location,
- status visualization.

### Finance / payroll
Study:
- high-trust approvals,
- payroll runs,
- transaction states,
- reconciliation,
- auditability,
- bulk work.

### Industrial / network / observability interfaces
Study:
- topology,
- health states,
- signal/motion,
- incidents,
- live operational data.

### Consumer-grade interaction quality
Study products outside ERP for:
- typography,
- motion,
- transitions,
- tactile feedback,
- search,
- command palettes,
- onboarding,
- responsive/adaptive layouts.

## Reference rule
Every adopted pattern must record:
- source/product,
- current date/version where relevant,
- what problem it solves,
- what HILTECH borrows conceptually,
- what HILTECH explicitly does NOT copy,
- mobile implications,
- desktop implications,
- accessibility/performance implications.

## Outputs
- Reference library.
- Pattern matrix.
- Anti-pattern library.
- Mobile interaction principles.
- Desktop interaction principles.
- Density rules.
- Navigation model.
- Motion reference board.
- Typography research.
- Iconography research.
- Data visualization research.
- HILTECH-specific original design thesis.

## Important
References inform the system; they do not define it. The final UI should feel specific to HILTECH's physical infrastructure, network, project, field, asset, and operational reality.
