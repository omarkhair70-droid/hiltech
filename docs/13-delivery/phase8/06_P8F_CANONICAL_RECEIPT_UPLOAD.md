## Actual implementation
- New target contract `FinanceExpenseReceiptEvidenceTargetPort` binds a binary receipt only to an existing immutable Phase8B `finance_expense_claim_draft` (org, expense ID, employee and creator identity).
- JDBC adapter refuses cross-person or revoked membership; only current authenticated original employee with active employment can reserve a receipt. Only the original active employee can reserve or finalize; read/download additionally allow an explicitly appointed current Finance reviewer (separate configured review key), never arbitrary members.
- Existing canonical `EvidenceLifecycleService` now accepts `FINANCE_EXPENSE_RECEIPT` on its own signed reserve/finalize/download lifecycle, not a new Finance file endpoint or storage system.
- Existing restricted `JdbcEvidencePersistence` inserts canonical `evidence` and `evidence_upload_session` under fixed `HIGHLY_RESTRICTED` + `INTERNAL_ONLY` constraints with `SIGNED_DOCUMENT` for PDF and `NATIVE_MEDIA` for PNG/JPEG. The existing object verifier checks content signature, SHA-256 and size and then marks valid content READY; there is **no proven anti-malware scan**, so READY must not be described as virus-free.
- Fixed `FINANCE_EXPENSE_RECEIPT_BINARY` requirement, target/evidence type, allowed PDF/PNG/JPEG content and existing max size. Cross-tenant and other-document reuse are forbidden.
- Command idempotency is provided by the same Evidence operation ID/transaction/audit mechanism; no financial approval or reimbursement is created.
- Test defaults OFF, outsider cannot upload, revoked membership cannot reserve/download; Phase8E carries real PostgreSQL tenant/creator/target/READY metadata source contract. Shared KMP client MockEngine tests assert signed private PUT, READY format-verification response and forged expense-target rejection before PUT. Targeted CI runs database, desktop common tests, and native compilation.

## API contract for existing canonical Evidence lifecycle
Reserve via existing Evidence API:
- `targetType=FINANCE_EXPENSE_RECEIPT`
- `targetId=` real expense draft UUID
- `evidenceRequirementKey=FINANCE_EXPENSE_RECEIPT_BINARY`
- `evidenceTypeCode=FINANCE_EXPENSE_RECEIPT`
- `workOrderId=null`, `supersedesEvidenceId=null`
- `contentType` PDF/PNG/JPEG; SHA256 and size from the actual file

Then upload through the **signed target generated by canonical Evidence**, finalize using existing finalize endpoint with exact session/hash/size, then read the canonical Evidence status. `READY` currently certifies the object's hash/size/type signature, **not antivirus clearance**. All access still requires current ownership/reviewer authority. It is NOT an expense approval.

## Finance privilege separation
`FINALIZE` for Finance receipts is accepted only for the originating current employee via `canReserve` authorization. Finance reviewers with current approval-authority binding can `VIEW`/`DOWNLOAD` evidence but cannot finish another employee's upload. No expense approval or transfer is implied.

- Android: `apps/androidApp/src/main/kotlin/com/hiltech/android/finance/FinanceAndroidReceiptPickerControl.kt` uses real `OpenDocument` system chooser, private bounded `ContentResolver` read, SHA-256 and no public cache. It calls the existing shared upload control, not a mock image.

- `FinanceReceiptBytes` is a single shared pre-upload byte-signature policy (PDF/PNG/JPEG), with cross-platform tests. It rejects extension/MIME spoofing before the signed reservation. Server S3 validation repeats the signature/hash/length checks after PUT.
- `FinanceExpenseReceiptUploaderTest` now uses actual PDF-prefixed bytes and correct digest, not synthetic `abc` mislabeled PDF. Desktop chooser signature contract and KMP bytes tests run in the targeted workflow.
- The receipt readiness query was corrected: signed PDF uses `SIGNED_DOCUMENT`; PNG/JPEG use `NATIVE_MEDIA`, not `ARBITRARY_FILE`. The PostgreSQL test asserts the valid positive case and negative mismatch cases.
- Finance reviewer can view/download when specifically authorized, but `FINALIZE` requires original active employee. This separation is now enforced in canonical Evidence operation dispatch.
