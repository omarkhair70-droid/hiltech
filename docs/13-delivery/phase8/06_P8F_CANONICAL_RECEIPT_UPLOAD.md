# Phase 8F — Canonical Finance expense receipt upload integration

Date: 2026-11-23
**Draft / integration review required; no feature is enabled by default.**

## Actual implementation
- New target contract `FinanceExpenseReceiptEvidenceTargetPort` binds a binary receipt only to an existing immutable Phase8B `finance_expense_claim_draft` (org, expense ID, employee and creator identity).
- JDBC adapter refuses cross-person or revoked membership; only current authenticated original employee with active employment can reserve a receipt. Read/download/finalize allow the creator or an explicitly appointed current Finance reviewer (separate configured review key), never arbitrary members.
- Existing canonical `EvidenceLifecycleService` now accepts `FINANCE_EXPENSE_RECEIPT` on its own signed reserve/finalize/download lifecycle, not a new Finance file endpoint or storage system.
- Existing restricted `JdbcEvidencePersistence` inserts canonical `evidence` and `evidence_upload_session` under fixed `HIGHLY_RESTRICTED` + `INTERNAL_ONLY` constraints with `ARBITRARY_FILE` scan/quarantine. No binary is treated as READY until existing scan pipeline transitions it.
- Fixed `FINANCE_EXPENSE_RECEIPT_BINARY` requirement, target/evidence type, allowed PDF/PNG/JPEG content and existing max size. Cross-tenant and other-document reuse are forbidden.
- Command idempotency is provided by the same Evidence operation ID/transaction/audit mechanism; no financial approval or reimbursement is created.
- Test defaults OFF, outsider cannot upload, revoked membership cannot reserve/download; Phase8E carries real PostgreSQL tenant/creator/target/READY metadata source contract. Shared KMP client MockEngine tests assert signed private PUT, QUARANTINED scan wait and later READY refresh, plus forged expense-target rejection before PUT. Targeted CI runs database, desktop common tests, and native compilation.

## Still not an operable end-to-end UI
- Native 8E Compose displays review status. 8F now adds typed `FinanceExpenseReceiptUploader` reusing `EvidenceApiClient` to call reserve -> signed private PUT -> finalize -> metadata refresh, plus `FinanceExpenseReceiptUploadControl` with a **real platform chooser callback**. Neither Android nor Windows shell yet mounts the callback with a real OS file-picker; that integration and device tests remain UX/DevOps-owned. - `hiltech.finance.expense-receipts.readiness-enabled` and `canonical-upload-ready` both default OFF; even after operator enablement, this **only** enables binary receipt evidence, never expense approval, invoice booking, transfer, Advance or Payroll.
- Finance expense approval, expense coding, tax/legal policy and reimbursement payment remain separate business work. No money transfer/back office posting here.
- Because this branch modifies shared Evidence files, it is a separate child PR on top of #185 and must be reviewed/coordinated with the Evidence/DevOps owner before merge. Avoid concurrent edits and rebase against canonical Evidence changes.

## API contract for existing canonical Evidence lifecycle
Reserve via existing Evidence API:
- `targetType=FINANCE_EXPENSE_RECEIPT`
- `targetId=` real expense draft UUID
- `evidenceRequirementKey=FINANCE_EXPENSE_RECEIPT_BINARY`
- `evidenceTypeCode=FINANCE_EXPENSE_RECEIPT`
- `workOrderId=null`, `supersedesEvidenceId=null`
- `contentType` PDF/PNG/JPEG; SHA256 and size from the actual file

Then upload through the **signed target generated by canonical Evidence**, finalize using existing finalize endpoint with exact session/hash/size, and wait until canonical security scanning changes state to READY. All access still requires current ownership/reviewer authority. It is NOT an expense approval.
