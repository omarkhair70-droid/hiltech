# Phase 10 — integration contract (Draft, never production enabled)

Source: PR #161, `IMPLEMENTATION_ORDER.md`, `04_PHASE10_SALES.md`, `SALES_COMMERCIAL_OBJECTS.md`.

* This lane owns **only** `server/.../commercial/**`, `database/phase10/**`, and optional standalone commercial UI/client files. Global desktop/android entry points, shared Gradle, shared auth/approval engine and numbered Flyway migrations belong to DevOps integration.
* `database/phase10/pending_commercial_schema.sql` is NOT an executable Flyway migration. Integration owner assigns a non-conflicting version after P7 V0060 and concurrent P8/P9/P11/P13. It must pass against an actual migrated PostgreSQL and be checked into `database/migrations/V....sql` by that owner.
* No privileges are seeded. `commercial_authority_binding` has explicit grant keys; require current HILTECH organization membership AND current binding at each operation. `hiltech.commercial.enabled` defaults **false**.
* Commercial quote versions contain customer sell prices only; internal costing sits in `commercial_boq_cost_line`. Never reclassify a supplier RFQ/quote as a client quote. A supplier quote may inform private costing via a future auditable reference, never via shared quote DTO.
* Shared `ApprovalEngineService` must approve a specific immutable quote version before release; absence of real company approval policy is a HARD BLOCK, not implicit consent. Contract signature and Client PO must use verified READY restricted Evidence before conversion.
* Existing `ProjectsService.createProject` owns actual project creation, code policy and project authorization. The Commercial handoff must be a single idempotent conversion; do not populate the old pre-commercial `project.source_opportunity_id` placeholders because V0021 forbids it. `commercial_project_handoff` is the external source-of-truth mapping.
* P8 Finance should consume `commercial_finance_award_source` as a typed/versioned source. This publishes **billing terms and IDs**, **not** a created invoice, receivable, payout or cash execution. P11 Support may read exact signed contract warranty fields once approved.
* Test matrix required before merge: current/revoked/cross-org memberships; operator vs cost/view vs release role; duplicate operationId; tenant FK; approved-version immutability; loss/withdrawn history; quote JSON negative cost leak; no unauthorized award; only one Project per won opportunity; source mismatches and retries; real native UI and Windows/Android compile; PostgreSQL migration and rollback/rehearsal.
* Real HILTECH redacted BOQ, tender, costing, contract, client PO and commercial approval policy are not supplied. **Release/actual client transmission/project conversion remain locked** until verified and signed off. No mail send or live pricing is automated.

## Expanded implementation checkpoint

- **10A:** Client-linked opportunity/RFQ/RFP/tender revisions, current identity and commercial authority; qualification with recorded discovery summary; planned/completed visits; lost/withdrawn reasons; all idempotent and audited. No invented probabilities.
- **10B:** Immutable scope, internal private cost/BOQ, client sell-only quote versions, exact ApprovalEngine subject-version review and database-enforced approved-only release. More recent quotes block release of older candidates.
- **10C:** Draft signed-contract/Client PO confirmation APIs require canonical Evidence IDs and independently READY finalized restricted file metadata. Company, target type/ID, size, hash and scan class recheck before conversion. Only ProjectsService.createProject may create the real Project; a unique composite-FK handoff maps the award.
- **Evidence hard blocker:** Existing EvidenceLifecycleService only accepts WORK_ORDER and EMPLOYEE_DOCUMENT upload targets. Commercial target uploads do NOT exist yet. JdbcCommercialAwardEvidenceGate verifies canonical Evidence metadata but does not mint it or bypass its permissions; actual signing/PO verification/project conversion fail closed until authorized commercial upload target integration is reviewed. READY verifies bytes, not legal validity or signature authenticity.
- **Finance 8:** commercial_finance_award_source publishes source keys (organization/opportunity/project/quote/contract/Client PO), exact quote revision, sell amount, currency and payment terms; not an invoice, maturity schedule, AR, tax, GL or payment. P8 must own booking and policies.
- **Projects 4 / Support 11:** commercial_project_scope_source and commercial_project_site_source expose technical scope/real Site source IDs without duplicate Project/Site/Work data; commercial_support_contract_source exposes actual signed contract coverage text without invented SLA, warranty periods or recurring work.
- **Native:** Shared Compose five-stage workspace and KMP CommercialDealCoordinator route authenticated, idempotent commands using exact JSON numeric values (never Double). Standalone modules are NOT mounted in Windows/Android global shells; DevOps/UX must mount after permitted role routing and real-device verification.
- **Authorities:** SALES_VIEW, SALES_WRITE, SALES_COST_VIEW, SALES_RELEASE, SALES_AWARD are independent. Revocation, membership expiry, tenant checks fail closed. ProjectAdmin is additionally required to create an actual Project. Commercial enabled flag remains OFF and no grants seeded.
