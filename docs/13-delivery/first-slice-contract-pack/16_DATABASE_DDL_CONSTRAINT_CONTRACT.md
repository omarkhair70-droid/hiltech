# 16 — First-Slice Database DDL / Constraint Contract

Status: **CONTRACT CANDIDATE v0.1 / PHYSICAL CONSTRAINTS DEFINED**
Date: 2026-09-18

## Purpose

Turn the first-slice table shapes into exact database integrity rules before production Flyway SQL is generated.

Production migrations are created only after FIRST_SLICE_FREEZE.

This file defines:
- keys,
- uniqueness,
- FK/delete behavior,
- CHECK constraints,
- partial uniqueness,
- required indexes,
- important transactional invariants.

Canonical table shapes:
`03_POSTGRES_FLYWAY_JOOQ.md`

---

# 1. Global conventions

## Primary keys
- UUID primary key for business/config aggregates.
- UUID generated by server/application before insert unless a table is naturally keyed by composite business context.
- no sequential database ID is exposed as public/business identity.

## Version
Mutable aggregates:
- version bigint NOT NULL DEFAULT 1
- CHECK (version >= 1)

## Time
- timestamptz for Instant.
- date for LocalDate.
- no local server timezone semantics in persistence.

## Decimal
- money/quantity use numeric/BigDecimal.
- stock quantity uses numeric(20,6).
- progress weights use numeric(20,6).

## Delete
Default:
- ON DELETE RESTRICT.
- history/business truth is closed/retired/superseded, not casually deleted.
- CASCADE only for purely owned technical child rows.
- SET NULL only for optional non-audit identity where loss is safe.

## State fields
- varchar + CHECK.
- no PostgreSQL enum type in first slice.

# 2. configuration

## config_revision

PK:
- id

CHECK:
- lifecycle_state IN ('DRAFT','ACTIVE','SUPERSEDED','RETIRED')
- revision_number > 0
- scope_type IN ('SYSTEM','ORGANIZATION')
- (scope_type='SYSTEM' AND scope_organization_id IS NULL)
  OR
  (scope_type='ORGANIZATION' AND scope_organization_id IS NOT NULL)
- effective_to IS NULL OR effective_from IS NULL OR effective_to > effective_from
- supersedes_id IS NULL OR supersedes_id <> id
- version >= 1

FK:
- scope_organization_id -> organization.id RESTRICT
- supersedes_id -> config_revision.id RESTRICT
- created_by -> user_identity.id RESTRICT
- activated_by -> user_identity.id RESTRICT

Unique:
- UNIQUE NULLS NOT DISTINCT (scope_type, scope_organization_id, family, code, revision_number)

Partial unique:
- only one ACTIVE revision per scope/family/code.

Index:
- (scope_type, scope_organization_id, family, code, lifecycle_state)
- supersedes_id
- effective_from/effective_to lookup when scheduled activation is later introduced.

## typed config child tables

Each typed config detail:
- config_revision_id PK/FK -> config_revision.id RESTRICT.
- family must match expected family through application validation + contract tests.
- no arbitrary executable script column.

# 10. Platform

## code_sequence

PK:
- (scope_type, scope_id, target_object_type, policy_code, sequence_period)

CHECK:
- next_value >= 1
- version >= 1

Note:
SYSTEM/organization nullable scope semantics must use an explicit non-null sentinel or a normalized scope-key column because NULL inside a PK is not allowed.
Recommended physical implementation:
- scope_key varchar NOT NULL, e.g. "org:{uuid}" / "project:{uuid}" / "site:{uuid}" / "type:{code}"
- PK(scope_key, target_object_type, policy_code, sequence_period)

## idempotent_operation

PK:
- operation_id

CHECK:
- state IN ('STARTED','APPLIED','FAILED')
- completed_at IS NULL OR completed_at >= created_at

Indexes:
- (actor_user_id, created_at DESC)
- partial unfinished WHERE completed_at IS NULL.

## audit_event

PK:
- id UUID

Append-only.
Application DB role used by normal commands has no update/delete path for immutable audit rows except dedicated retention/admin procedure where policy permits.

Indexes:
- (target_type, target_id, occurred_at DESC)
- (actor_user_id, occurred_at DESC)
- correlation_id
- trace_id where stored

# 11. Constraint-test gate

Before FIRST_SLICE_FREEZE contract is promoted:

Database integration tests must prove:

- config scope uniqueness including SYSTEM null scope behavior.
- one ACTIVE config revision.
- WorkOrder project/site/projectSite consistency.
- one current WorkPolicyBinding.
- instruction revision uniqueness.
- duplicate active assignment blocked.
- stale WorkOrder version produces zero-row optimistic update.
- one primary active AssetTag.
- one Asset custody projection.
- stock balance cannot violate nonnegative/conservation checks.
- duplicate operation cannot create duplicate movement/evidence/command side effect.
- evidence >16 MiB rejected.
- expired upload session cannot finalize.
- Asset checkout race produces one winner.
- active reservation collision policy.
- authorization pending revoke fail-closed path.
- project progress projection cannot exceed 100%.
- invalid state strings rejected.
