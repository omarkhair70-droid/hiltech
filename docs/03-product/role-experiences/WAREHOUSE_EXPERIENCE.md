# Complete Role Experience — Warehouse

Status: PRODUCT MODEL v0.1 / NOT BUILD-READY

## Product thesis
Warehouse work should become scan-first, custody-aware, auditable, and tied directly to projects and finance.

## Mobile home
- Items to issue today
- Items due back
- Deliveries to receive
- Low stock
- Overdue assets
- Damaged/calibration queue
- Quick Scan

## Desktop
- Inventory
- Reservations
- Receiving
- Checkout/Return
- Transfers
- Stocktake
- Maintenance/Calibration
- Discrepancies
- History
- Procurement linkage

## Key commands
- receive goods
- register/tag asset
- reserve
- checkout
- return
- transfer
- inspect condition
- stock count
- report damage/loss
- request adjustment
- send for repair/calibration

## Scan-first UX
Primary field actions should start from scanning the person/item/context where practical rather than searching giant tables.

## Automation
- due-return reminders
- low stock
- calibration block
- reservation conflict
- tomorrow issue preparation
- anomaly correlation with access events

## Permissions
Warehouse user can move inventory but cannot silently approve write-off/value changes unless separately authorized.

## Offline
Cycle counts and temporary scan queues may work offline; high-risk stock adjustments require online authority.

## Edge states
- unreadable QR
- duplicate asset tag
- asset expected but physically missing
- return with damage
- partial return
- item already checked out
- discrepancy between PO and delivery
- offline scan collision
- camera/access source unavailable

## Success
HILTECH can answer where every important tool is, who is responsible, and what movement created that state.
