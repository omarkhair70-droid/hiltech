# Complete Role Experience — Engineer

Status: PRODUCT MODEL v0.1 / NOT BUILD-READY

## Product thesis
Engineering work should turn technical reality into structured, traceable evidence tied to the correct project/site/link/asset.

## Mobile home
### Engineering Today
- assigned technical visits
- tests due
- drawings/spec updates
- technical issues
- reviews requiring engineer action

## Desktop
- technical project view
- drawings/specifications
- topology/asset relationships
- test/evidence review
- technical issues
- changes/RFIs
- bulk verification
- reports

## Key commands
- open latest approved drawing/spec
- record measurement/test
- attach evidence to exact object
- create technical issue
- approve/reject technical result within authority
- request design/field clarification
- mark technical acceptance/rework

## Evidence model
No orphan uploads.
Photo/test/measurement/report must link to:
Project -> Site -> Work/Asset/Link/Test context.

## Automation
- warn if old drawing opened after a newer approved revision exists
- flag missing mandatory test
- detect calibration-invalid test equipment where known
- carry structured test results into handover package

## Offline
High priority:
- drawings/spec cache
- assigned work
- test entry
- photo/evidence queue
- asset/link context

## Edge states
- wrong drawing revision
- test equipment calibration expired
- duplicate serial
- test fail
- evidence uploaded to wrong context
- offline conflicting technical update

## Cross-role
PM supplies work context.
Supervisor/Technician supply field evidence.
Engineer returns technical acceptance/rework.
Client receives only approved technical artifacts.

## Success
Technical history can be reconstructed from HILTECH without searching WhatsApp/file folders.
