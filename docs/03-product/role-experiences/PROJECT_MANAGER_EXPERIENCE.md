# Complete Role Experience — Project Manager

Status: PRODUCT MODEL v0.1 / NOT BUILD-READY

## Product thesis
The PM should run delivery from one live project truth instead of reconstructing reality from calls, chats, spreadsheets, warehouse questions, and field reports.

## Primary home
### My Projects
Each card/row exposes:
- health
- progress
- next milestone
- blockers
- team readiness
- material/equipment readiness
- client action
- commercial flag where allowed

## Desktop Command Center
- portfolio list
- project health
- schedule/work breakdown
- sites
- teams
- resource readiness
- issue/change queue
- client actions
- documents/evidence
- project financial context where permitted

## Mobile
- Today
- approvals/actions
- site quick view
- work orders
- blockers
- client actions
- scan/open asset
- quick assign/reassign where authorized

## Project detail
Overview / Sites / Work / People / Materials / Equipment / Documents / Issues / Changes / Client / Handover / Finance-permission.

## Key commands
- create/update work package
- assign work
- request material/equipment
- request procurement
- escalate blocker
- request approval
- publish client-visible update
- submit variation
- accept/reject reviewed work where authority allows
- initiate handover

## Automation
- readiness calculation
- overdue/blocker detection
- progress derived from accepted work
- resource conflict warnings
- handover completeness detection
- client pending-action reminders

## Notifications
Only assigned-project relevant:
- blocker
- missed dependency
- client response
- material/equipment shortage
- rework
- approval result
- milestone risk

## Offline
Project/site context, drawings, assigned work, and evidence review should support cached access. Critical approvals/commercial changes require online authority.

## Edge states
- project data incomplete
- stale schedule
- work completed but evidence missing
- material reserved but not issued
- employee reassigned
- client rejects variation
- work completed offline then conflicts on sync
- project permission removed

## Cross-role handoffs
Sales -> PM: won scope and commitments.
PM -> Field: work/resources/context.
Field -> PM: accepted evidence/progress.
PM -> Warehouse: reservations.
PM -> Procurement: shortages.
PM -> Client: controlled progress/approvals.
PM -> Finance: milestone eligibility/cost context.
PM -> Owner: exceptions only.

## Success
PM can answer “what is blocking delivery?” without calling five people.
